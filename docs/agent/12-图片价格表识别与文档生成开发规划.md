## 1. 规划结论

WPS 的流程适合“把图片制作成一份可阅读文档”，本项目需要在此基础上增加业务系统必须具备的结构化、复核、版本、审批和审计能力。

新的主流程为：

```text
图片获取与质量检查
  → 表格 OCR 与单元格结构恢复
  → 原文/规范值双轨保存
  → 版面复核与业务字段映射
  → 创建不可变输出快照
  → 生成可编辑 XLSX + 可阅读 PDF
  → 鉴权下载/分享
  → 可选进入价格更新或采购入库的独立审批流程
```

核心决定：

1. **OCR 必须输出单元格结构，不能只输出纯文本。** 至少保存行列位置、原文、置信度和原图区域。
2. **原始识别值与规范值分开。** 例如原文 `6·5` 可以给出规范候选 `6.5`，但未经确认不得覆盖原文。
3. **先复核，后生成。** PDF/XLSX 只能读取用户确认过的任务快照，不能直接读取临时 OCR 文本。
4. **XLSX 是可编辑交付物，PDF 是稳定阅读、打印和转发的交付物。** 不把普通 PDF 描述成可编辑文档。
5. **文档生成不等于业务写入。** 更新商品进价、创建采购单或入库必须进入现有 `R2_WRITE` 审批链路。
6. **首版采用云端表格 OCR，保留私有化替换能力。** 当前项目使用 CloudBase/COS，MVP 优先接入腾讯云表格识别；通过 Provider 接口预留 PaddleOCR PP-StructureV3。
7. **复用现有 `ExcelTask` 主链路。** 不另建一套图片任务、复核和输出系统；新增 `document` 门面和 OCR 适配层即可。
8. **文档数字化与视觉理解分成两条链路。** 视觉模型可以回答“图片里有什么、哪里异常”，但不得作为价格、数量和行列结构的唯一数据源。
9. **图像预处理成为独立、可观测的步骤。** 自动旋转、透视矫正、裁剪和增强必须保留参数及变换关系，保证 OCR 坐标能映射回原图。

## 2. 与 WPS 流程的对应关系

| WPS 环节 | 本项目实现 | 增加的业务保障 |


## 3. 当前基础与真实缺口

### 3.1 已有能力

- Agent 附件入口已经支持 JPG、PNG、WEBP，并能保存原图。
- `AttachmentContentParser` 已预留 `agent.attachment.ocr-url`，但当前只读取 OCR 返回的 `text`。
- `ExcelTask` 已具备上传、解析、字段映射、商品匹配、逐行复核、整单校验、幂等提交和版本控制。
- 文件任务已经可以生成规范 XLSX。
- 报价任务已经可以生成 XLSX/PDF，输出文件具备记录、鉴权下载和有效期。
- PDF 生成、中文字体处理和人工渲染检查已有实现基础。

### 3.2 主要缺口

1. 图片尚不能作为正式 `ExcelTask` 数据源。
2. OCR 协议只有纯文本，没有行列、合并单元格、坐标和置信度。
3. 没有图片质量检查、透视/截断提示和重拍引导。
4. 没有保存 OCR 原始响应、Provider、模型版本和请求 ID。
5. 没有“左侧原图定位、右侧单元格编辑”的图片复核界面。
6. 行级结果缺少 `rawValue`、`normalizedValue`、`confidence`、`sourceRegion` 和确认状态。
7. 输出仍以买家报价为主，缺少通用“原样价格表”和“规范价格表”模板。
8. Agent 尚不能把图片附件转换为正式文件任务并引导用户完成复核。

## 4. 产品边界

### 4.1 首版支持

- 单张 JPG/PNG/WEBP 表格图片；
- 中文印刷体价格表；
- 有线表格为主，兼容简单无线表格；
- 表头识别与人工调整；
- 名称、规格、单位、数量、单价、备注等字段映射；
- 单元格级人工修改；
- 生成标准 XLSX 和 PDF；
- 原图、识别结果、修改和输出可追溯。

### 4.2 首版不承诺

- 恢复图片外被截断的列或文字；
- 无人复核直接更新商品价格或库存；
- 像素级复刻任意原表样式；
- 手写体、严重反光、极端透视图片的全自动识别；
- 通用 PDF 编辑；
- 让大模型直接决定价格或覆盖 OCR 原文。

## 5. 双链路与总体架构

### 5.1 文档数字化链路

用于“把图片转换成可编辑表格、XLSX 或 PDF”，是价格表和采购单的主链路：

```text
图片
  → 图像预处理
  → OCR 文字与坐标
  → 表格结构识别
  → 规范化业务行
  → 人工复核
  → XLSX/PDF/JSON
```

这条链路要求结果可重复、可定位、可校验、可审计。所有数量、价格和商品匹配都必须来自结构化结果。

### 5.2 视觉理解链路

用于以下请求：

- “图片中大概有哪些商品？”
- “这张图片是否模糊、缺列或有异常？”
- “两张采购单的版面有什么明显变化？”
- “下一步应该调用哪个文档工具？”

```text
图片/低分辨率预览
  → 视觉模型
  → 语义描述、问答或工具路由建议
```

视觉结果只能作为解释、提示和路由依据。涉及金额、数量、规格、行列和正式业务动作时，必须回到文档数字化链路，并经过确定性校验与用户确认。

### 5.3 服务架构

```text
微信小程序
├─ 拍照/相册选择
├─ 上传前质量提示
├─ 任务进度
└─ 原图 + 表格复核
        ↓
DocumentTaskController（门面）
        ↓
DocumentInspectionService
├─ 文件安全检查
├─ 分辨率/模糊/曝光/截断提示
└─ 表格区域检测
        ↓
ImagePreprocessingService（OpenCV）
├─ EXIF/方向修正与自动旋转
├─ 倾斜、透视矫正
├─ 表格裁剪、去噪、对比度增强
└─ 保存变换矩阵，坐标可映射回原图
        ↓
TableOcrProvider
├─ TencentTableOcrProvider（MVP）
├─ PaddleTableOcrProvider（后续/私有化）
└─ WpsImageConversionProvider（可选转换/兜底）
        ↓
OcrResultNormalizer
├─ 单元格坐标统一
├─ 行列矩阵恢复
├─ 原文与规范候选
└─ 低置信度和结构异常
        ↓
ParsedWorkbookAdapter
        ↓
现有 ExcelTask 映射、匹配、复核、校验
        ↓
DocumentSnapshotService
        ↓
XLSX Renderer + PDF Renderer
        ↓
现有 AttachmentStorage / ExcelTaskOutput / 鉴权下载
```

旁路能力：

```text
原图 → VisionUnderstandingGateway → 图片问答/异常解释/工具选择
```

模型只负责理解用户意图、选择工具和解释异常。OCR、行列恢复、金额计算、权限、版本、幂等和文件生成均由确定性服务完成。

### 5.4 图像预处理约束

预处理不能只覆盖原文件后再送 OCR。系统应保存：

- 原图对象和 SHA-256；
- 预处理图对象和处理版本；
- 自动旋转角度；
- 透视变换矩阵；
- 裁剪区域；
- 质量评分和警告；
- OCR 使用的是原图还是预处理图。

OCR 返回的多边形先映射到预处理图，再通过逆变换映射到原图。前端高亮必须使用原图坐标，避免用户看到的定位区域与 OCR 实际区域错位。

## 6. OCR 统一协议

### 6.1 Provider 接口

```java
public interface TableOcrProvider {
    TableOcrResult recognize(TableOcrRequest request);
}
```

```java
public record TableOcrCell(
        int tableIndex,
        int rowStart,
        int rowEnd,
        int columnStart,
        int columnEnd,
        String rawText,
        BigDecimal confidence,
        List<OcrPoint> polygon) {
}
```

Provider 返回值还必须包含：

- `provider`；
- `modelVersion`；
- `requestId`；
- `detectedAngle`；
- 原图宽高；
- 表格列表；
- 单元格列表；
- 警告；
- 原始响应对象存储位置或摘要。

Provider 能力声明应包含：

```text
supportsCellCoordinates
supportsMergedCells
supportsMultipleTables
supportsAsyncJobs
supportsNativeXlsx
maxImagesPerTask
maxBytesPerImage
```

业务服务根据能力声明选择流程，不能假设所有 OCR 服务都同步返回相同字段。WPS 图片转文档属于异步 Provider：提交后保存远端 `task_id`，通过后台任务查询结果；测试应用的图片数量和大小限制应作为可配置 Provider 限制，不写死在公共业务规则中。

### 6.2 为什么不能继续只返回 `text`

纯文本会丢失：

- 单元格所属行列；
- 空单元格；
- 合并单元格；
- 原图位置；
- 单元格置信度；
- 多表格边界。

因此现有 `AttachmentContentParser.parseImage()` 可以继续为 Agent 提供简短阅读文本，但正式价格表导入必须走结构化 `TableOcrProvider`，二者不能混为一个协议。

## 8. 识别与校验规则

### 8.1 图像质量门禁

上传后先检查：

- 最短边分辨率；
- 模糊程度；
- 过曝/欠曝；
- 图片长宽比；
- 旋转角度；
- 表格是否触及图片边缘；
- 是否只拍到局部表格。

质量差不直接等同于失败。系统应返回“可继续识别，但建议重拍”或“无法可靠识别，请重拍”两级提示。

预处理首版使用 OpenCV 独立服务或受控进程，执行顺序为：

```text
读取 EXIF 方向
  → 自动旋转
  → 检测最大表格/文档四边形
  → 透视矫正
  → 裁剪无关背景
  → 灰度/局部对比度增强
  → 轻量去噪
  → 输出质量指标与预处理图
```

二值化不是所有拍屏图片的默认步骤。摩尔纹、彩色底纹和细网格线场景应通过金标集比较原图、增强图和二值图，再选择 OCR 输入；过度二值化可能破坏小数点和细表格线。

拍摄提示：

- 优先上传原始截图或 Excel；
- 拍摄屏幕时尽量正对，避免摩尔纹；
- 必须包含完整表头和表格四边；
- 一张图片只拍一张主要表格；
- 避免反光、阴影和聊天软件二次压缩。

### 8.2 值规范化

只生成候选，不静默覆盖：

```text
6·5  → 候选 6.5
６.５ → 候选 6.5
2×150 → 候选 2*150（当字段为规格时）
￥ 12.00 → 候选 12.00（当字段为价格时）
```

规范化必须结合目标字段。`2*150` 在规格列是字符串，在金额表达式中也不得自动执行乘法。

### 8.3 自动通过与人工复核

自动通过不能只看 OCR 置信度，还要同时满足：

- 表格结构完整；
- 字段类型合法；
- 商品名称或条码可唯一匹配；
- 价格、数量在业务允许范围内；
- 与历史值的变化未触发异常阈值；
- 行列没有截断或跨行冲突。

任何一项不满足即进入 `NEEDS_REVIEW`。阈值必须通过真实样本校准，不能在第一版写死为“置信度大于某个数就绝对正确”。

## 10. 前端体验

### 10.1 上传页

提供三个入口：

```text
上传原始 Excel（最准确）
上传截图
拍摄纸质/屏幕表格
```

不要把三种入口包装成相同准确率。若用户能取得原始 Excel，应明确优先推荐 Excel。

### 10.2 识别进度

展示真实阶段，不伪造统一百分比：

```text
正在检查图片
正在识别表格
正在恢复行列
正在匹配业务字段
等待复核
```

### 10.3 结构复核页

桌面/平板：左侧原图，右侧表格。  
手机：上方原图裁剪，下方当前行编辑卡。

要求：

- 点击单元格时高亮对应原图区域；
- 显示原文、规范值和置信度；
- 黄色表示低置信度，红色表示校验失败，蓝色表示已自动规范化；
- 可以筛选“仅看异常/低置信度/未匹配”；
- 支持修改表头行、删除误识别行、补充空单元格；
- 每次保存携带 `expectedVersion`。

### 10.4 输出确认

确认卡至少展示：

```text
来源图片：1 张
识别表格：1 个
有效数据：32 行
已人工修正：4 格
仍有警告：2 行
输出：XLSX + PDF
版式：标准价格表
业务写入：否
```

## 11. PDF 与 XLSX 输出

### 11.1 输出模式

首版提供两种模板：

1. `SOURCE_LIKE_TABLE`：尽量保持原字段顺序和空值，用于归档和转发；
2. `NORMALIZED_PRICE_TABLE`：输出名称、规格、单位、供应商编码、价格、备注等规范字段，用于后续处理。

### 11.2 XLSX

XLSX 是可编辑版本，至少包含：

- `识别结果`；
- `异常与未确认`；
- `生成说明`。

`生成说明` 记录原图 SHA-256、OCR Provider、任务版本、模板版本、生成时间和操作人。

### 11.3 PDF

PDF 是稳定阅读和打印版本：

- A4 横向或纵向由列数自动选择；
- 表头跨页重复；
- 长名称和规格自动换行；
- 数值右对齐；
- 页脚包含页码、任务编号和生成时间；
- 警告和无法确认的数据不得静默消失；
- 中文字体随应用部署；
- 生成后必须渲染为图片检查裁切、乱码、黑块和越界。

## 12. Agent 工具

在现有文件任务工具基础上新增或调整：

### 12.1 `create_image_table_task`

- 风险：`R1_DRAFT`；
- 输入：附件 ID、用途、供应商 ID（可选）；
- 输出：任务 ID、质量检查、表格数、行数和问题数；
- 行为：只创建暂存任务。

### 12.2 `get_document_review_summary`

- 风险：`R0_READ_ONLY`；
- 输出：字段映射、低置信度单元格、无效行和商品匹配摘要。

### 12.3 `apply_document_row_values`

- 风险：`R1_DRAFT`；
- 输入：任务 ID、任务版本，以及使用稳定 `resultId` 定位的行级修改；
- Agent 可把自然语言中的数量和单价转换为候选修改，但后端必须按已确认规格精确匹配；
- 同名多规格、单位冲突或一段话中的值数量对不上时拒绝批量应用并要求复核；
- 金额由后端使用 `BigDecimal` 计算。

示例：

```json
{
  "taskId": 108,
  "expectedVersion": 7,
  "items": [
    {"resultId": 101, "quantity": 10, "unitPrice": 3.20}
  ]
}
```

### 12.4 `generate_document_files`

- 风险：`R1_DRAFT`；
- 输入：任务 ID、任务版本、模板和输出格式；
- 执行前展示结构化确认；
- 生成文件，不修改价格、库存或订单。

### 12.5 `analyze_document_image`

- 风险：`R0_READ_ONLY`；
- 走视觉理解链路，只回答清晰度、可见区域、显著异常和下一步建议；
- 返回值必须标注为视觉解释，不进入 `ExcelTask` 行数据；
- 若用户要求转换、计算或写入，工具应引导创建结构化文档任务。

### 12.6 暂不允许模型执行

- 根据模糊文字自动选择同名商品；
- 未经确认修正价格；
- 从图片识别结果直接更新所有商品进价；
- 生成文件后自动采购入库。

## 13. 状态机

```text
UPLOADED
  → QUALITY_CHECKING
  → OCR_PROCESSING
  → STRUCTURE_NORMALIZING
  → READY_FOR_MAPPING
  → READY_FOR_REVIEW
  → READY_FOR_OUTPUT
  → OUTPUT_GENERATING
  → OUTPUT_READY
```

异常与人工分支：

```text
QUALITY_CHECKING → NEEDS_BETTER_IMAGE | FAILED
OCR_PROCESSING → WAITING_OCR | OCR_FAILED
STRUCTURE_NORMALIZING → NEEDS_STRUCTURE_REVIEW
READY_FOR_REVIEW → NEEDS_REVIEW
OUTPUT_GENERATING → OUTPUT_PARTIAL_FAILED | OUTPUT_FAILED
```

数据库仍是真实状态源。OCR 请求、输出任务和 Agent Run 都必须支持断线后查询，不依赖小程序页面持续打开。

## 14. 分阶段开发计划

### P0：识别效果验证与金标集

目标：在写正式业务代码前确定 OCR 路线和真实上限。

- 收集 30～50 张真实价格表图片；
- 覆盖截图、拍屏、纸张、倾斜、阴影、无线表格和局部截断；
- 人工标注表头、单元格文本和行列位置；
- 对比腾讯云表格识别与 PaddleOCR；
- 统计价格字段准确率、单元格准确率、结构准确率和需要复核比例；
- 确定首发 Provider、降级条件和初始阈值。

验收：形成可重复运行的评测集和结论报告，不以单张演示图效果作为选型依据。

### P1：结构化 OCR 后端闭环

目标：图片可以成为正式文件任务。

- 实现 OpenCV 预处理服务、变换参数保存和坐标逆映射；
- 实现 `TableOcrProvider` 和腾讯云适配器；
- 增加图片质量检查以及原图/增强图输入选择；
- 保存 OCR 元数据和原始响应；
- 将 OCR 单元格转换为 `ParsedWorkbook`；
- 图片接入现有 `ExcelTask` 异步状态与版本控制；
- 增加失败重试、超时和 Provider 错误映射；
- 补单元测试、契约测试和真实图片集回归。

验收：上传图片后能得到稳定行列结构，空格、原文、置信度和坐标不丢失，不写业务主表。

### P2：结构复核与业务映射

目标：用户能看懂、修正并确认识别结果。

- 增加 OCR 单元格表和逐格 PATCH；
- 实现原图区域高亮；
- 表头行调整、误识别行删除和缺失格补录；
- 复用字段映射、商品候选与逐行审核；
- 增加价格、规格、数量的字段感知规范化；
- 增加版本冲突和并发编辑处理。

验收：低置信度和结构异常不会静默通过，所有人工修改可追溯。

### P3：同源 XLSX/PDF 输出与交付

目标：复核后的同一份数据可以稳定交付。

- 创建不可变输出快照；
- 增加 `SOURCE_LIKE_TABLE` 与 `NORMALIZED_PRICE_TABLE`；
- 复用并整理现有 XLSX/PDF 渲染器；
- 增加输出批次、部分失败和单格式重试；
- XLSX 回读校验；
- PDF 页面渲染校验；
- 接入现有鉴权下载、有效期和输出记录。

验收：XLSX/PDF 行数、字段、价格和任务版本一致，中文不乱码、不越界，不同用户不可越权下载。

### P4：Agent 对话闭环

目标：用户可以在“小五”中完成上传、检查、复核引导和文件生成。

- 注册结构化文档工具和只读视觉分析工具；
- 附件识别后创建图片表格任务；
- Agent 解释质量问题和复核项；
- 输出前显示结构化确认卡；
- 结果消息展示 XLSX/PDF 独立状态；
- 模型不可用时仍可在传统页面完成全部流程。

验收：Agent 只编排，不绕过确定性校验；歧义行必须进入复核。

### P5：业务写入与规模化

目标：在文档闭环稳定后，选择性进入价格或采购业务。

- 将已确认任务转换为 `SUPPLIER_PRICE` 更新预览；
- 或转换为 `PURCHASE_RECEIPT` 任务；
- 重新查询实时商品和价格；
- 独立 `R2_WRITE` 审批、幂等提交和审计；
- 评估 PaddleOCR 私有部署、模型微调、批量多图和成本路由。

验收：文档生成和业务写入完全解耦，拒绝或失败不会影响已生成文件。

## 15. 测试与指标

### 15.1 离线识别指标

- 单元格文字完全匹配率；
- 数字/价格字段完全匹配率；
- 行列结构正确率；
- 完整行召回率；
- 表头识别率；
- 自动规范化正确率；
- 需要人工复核的单元格比例。

### 15.2 业务质量指标

- 经人工确认后的价格错误数；
- 用户平均修正格数；
- 从上传到可输出的中位耗时；
- OCR 重试率和失败率；
- 图片因质量不足被要求重拍的比例；
- 输出部分失败率；
- 越权下载和重复写入必须为零。

### 15.3 必测样例

- `6·5` 与 `6.5`；
- `0·` 或右侧被截断；
- `2*150`、`8×200` 等规格；
- 空单元格和合并单元格；
- 同名不同规格商品；
- 图片仅包含表格中间部分；
- 拍屏摩尔纹；
- 旋转、透视、阴影和反光；
- OCR 服务超时、限流和返回空表格；
- PDF 成功而 XLSX 失败，以及反向部分失败；
- 恶意公式文本和附件提示注入。

## 16. MVP 验收标准

- 支持 JPG/PNG/WEBP 创建图片表格任务；
- 表格 OCR 返回并保存单元格行列、原文、置信度和原图位置；
- 原文与规范值可以逐格对照和修改；
- 低置信度、截断和无效价格不会静默通过；
- 图片结果可以复用现有字段映射和商品匹配；
- 输出前存在结构化确认；
- XLSX 和 PDF 来自同一快照且内容一致；
- 输出可鉴权下载、过期、重试和审计；
- 生成文件不会自动修改商品、供应商价格、库存或订单；
- OCR 或模型不可用时，任务进入可解释状态并允许重试或人工处理。

## 17. 推荐开发顺序

下一轮只推进 P0 和 P1，不同时做 Agent 对话、WPS 云文档同步或采购入库：

1. 建立真实图片金标集；
2. 用腾讯云表格识别完成一次离线评测；
3. 用同一金标集验证 OpenCV 预处理是否真实提升识别效果；
4. 固化内部 OCR JSON 契约和 Provider 能力声明；
5. 实现预处理、Provider、元数据存储和 `ParsedWorkbook` 适配；
6. 图片接入现有文件任务状态机；
7. 用金标集做自动回归；
8. P1 验收后再进入复核页面开发。

这样首个交付验证的是“图片能可靠成为可复核的数据任务”，而不是仅证明“某一张图可以生成一个看起来不错的 PDF”。
