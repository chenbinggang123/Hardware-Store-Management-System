# 五金店经营 Agent 产品设计

## 1. 产品定义

### 1.1 一句话定位

面向个体经营者的私人店务 Agent，让用户按照自己的语言和习惯完成查货、开单、记账、补货和经营分析。

### 1.2 核心承诺

用户照常说、照常做，Agent 负责理解、查找和准备；涉及钱、货和正式业务状态时，始终由用户确认。

### 1.3 非目标

- 不以聊天时长或回答数量作为产品价值。
- 不要求用户学习复杂的 AI 提示词。
- 不用 Agent 替代所有传统页面。
- 不允许模型绕过业务规则直接修改数据。

## 2. 目标用户

### 2.1 核心用户

- 五金店店主或夫妻店经营者。
- 日常同时承担销售、采购、库存和记账工作。
- 熟悉商品和客户，但不愿学习复杂软件。
- 高频使用微信和语音输入。
- 重视效率，也高度担心价格、库存和欠款出错。

### 2.2 用户心理

| 用户心理 | 产品响应 |
| --- | --- |
| 希望少操作，但不希望 AI 自作主张 | 草稿优先、关键动作确认 |
| 认为自己的经营方式很特殊 | 支持别名、个人价格规则和流程偏好 |
| 不愿学习复杂系统 | 提供任务入口、示例问题和快捷操作 |
| 害怕数据和账目出错 | 展示依据、变更前后值和执行记录 |
| 厌恶重复确认 | 根据风险等级决定是否确认 |
| 担心被平台绑定 | 支持数据导出、关闭记忆和传统页面操作 |

## 3. 核心使用场景

### 3.1 经营查询

示例：

- “东成电钻还有几台？”
- “王师傅还欠多少钱？”
- “今天卖了多少？”
- “哪些商品快没货了？”

产品要求：查询应直接返回事实、数据时间和可继续执行的快捷动作。

### 3.2 自然语言开单

示例：

> 给老王开两个东成电钻，还是上次价格，先记账。

标准流程：

1. 识别客户、商品、数量和付款意图。
2. 搜索候选客户和商品。
3. 对不确定项要求用户选择。
4. 查询历史价格和实时库存。
5. 生成销售单草稿。
6. 展示金额、库存和欠款变化。
7. 用户确认后创建正式销售单。
8. 出库作为独立高风险动作再次确认。

### 3.3 个性化学习

用户纠正一次后，Agent 可以建议保存：

- 商品俗称对应关系。
- 客户常用称呼。
- 客户默认价格策略。
- 默认付款方式。
- 是否自动进入出库确认。

保存前必须明确区分：

- 仅本次使用。
- 对当前客户长期生效。
- 对当前商品类别生效。
- 作为全店默认规则。

## 4. 产品形态

产品采用三种入口并存：

| 入口 | 适用情况 | 示例 |
| --- | --- | --- |
| 快捷操作 | 高频且确定 | 扫码、收款、入库 |
| Agent | 复杂、口语化、有上下文 | 一句话开单、查经营原因 |
| 传统页面 | 精确编辑、异常处理 | 完整表单、明细查看 |

首页不设计为空白聊天页，而是由以下区域组成：

- 今日重点事项。
- Agent 输入框。
- 快捷任务。
- 最近任务。
- 待确认动作。

## 5. MVP 用户旅程

```text
用户进入 Agent 首页
→ 点击示例或输入一句话
→ Agent 查询客户和商品
→ 有歧义时显示候选卡片
→ Agent 生成销售草稿
→ 用户检查金额、库存和欠款影响
→ 用户确认创建
→ 系统返回订单结果和下一步动作
```

### 5.1 成功标准

- 新用户无需培训即可完成首次 Agent 开单。
- 用户能明确判断 Agent 当前是查询、草稿还是正式执行。
- 出错时用户知道如何修改、取消或转到传统页面。
- 同一句确认不会创建两张订单。

## 6. MVP 范围与优先级

### P0

- 文本对话。
- 客户搜索与候选选择。
- 商品搜索与候选选择。
- 库存查询。
- 历史价格查询。
- 销售草稿。
- 人工确认创建销售单。
- Agent 操作日志。

### P1

- 语音转文字与发送前校正。
- 用户商品别名。
- 草稿多轮修改。
- Agent 任务历史。
- 失败回退传统开单页。

### P2

- 图片录单。
- 补货建议。
- 采购草稿。
- 主动经营提醒。
- 经营日报。

## 7. 产品指标

### 7.1 北极星指标

通过 Agent 成功完成的有效经营任务数。

“有效”要求任务已经产生用户认可的查询结果、草稿或正式业务结果，不能只计算聊天消息。

### 7.2 效率指标

- Agent 开单平均耗时。
- 相比传统表单减少的操作步骤。
- 每个任务平均追问次数。
- 草稿一次确认率。

### 7.3 质量指标

- 客户匹配 Top-1/Top-3 准确率。
- 商品匹配 Top-1/Top-3 准确率。
- 数量和金额提取准确率。
- 应追问未追问率。
- 错误执行率。
- 重复执行率。

### 7.4 信任指标

- 用户主动确认率。
- 用户撤销或纠正率。
- 保存个性化记忆的比例。
- Agent 失败后继续使用的比例。

## 8. 待验证假设

1. 用户更愿意用语音而不是键盘完成开单。
2. 销售开单比经营问答更能形成持续使用。
3. 用户愿意在首次发生时确认商品别名。
4. 用户能理解“草稿”和“正式订单”的区别。
5. 展示建议依据能显著提高确认率。
6. 对个体商户而言，候选选择比 Agent 自动猜测更容易建立信任。
