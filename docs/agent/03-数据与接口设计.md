# Agent 数据与接口设计

## 1. 设计原则

- Agent 运行数据与正式业务数据分离。
- 正式订单只能通过现有业务 Service 和事务写入。
- 所有表预留 `tenant_id`，为多用户数据隔离做准备。
- JSON 用于保存运行快照，不作为正式订单明细的数据真源。
- 关键记录包含版本、创建时间和更新时间。

## 3. API 设计

### 3.1 发送消息

`POST /api/agent/sessions/{sessionId}/messages`

```json
{
  "clientMessageId": "msg-client-001",
  "type": "TEXT",
  "content": "给老王开两个东成电钻，还是以前价格，先记账"
}
```

返回结果可能是：

- `FINAL_TEXT`
- `CANDIDATE_SELECTION`
- `ACTION_PREVIEW`
- `RUNNING`
- `FAILED`

### 3.2 选择候选项

`POST /api/agent/runs/{runId}/selections`

```json
{
  "selectionType": "CUSTOMER",
  "candidateId": 102,
  "runVersion": 3
}
```

### 3.3 审批动作

`POST /api/agent/actions/{actionId}/approve`

```json
{
  "actionVersion": 1,
  "confirmationToken": "opaque-token"
}
```

### 3.4 拒绝动作

`POST /api/agent/actions/{actionId}/reject`

```json
{
  "actionVersion": 1,
  "reason": "价格需要重新确认"
}
```

### 3.5 查询运行状态

`GET /api/agent/runs/{runId}`

用于异步处理、断线恢复和页面刷新。

## 5. 工具错误协议

工具不向模型返回堆栈信息，统一返回：

```json
{
  "success": false,
  "errorCode": "PRODUCT_AMBIGUOUS",
  "message": "找到多个匹配商品，需要用户选择",
  "retryable": false,
  "userActionRequired": true,
  "details": {}
}
```

建议错误码：

```text
CUSTOMER_NOT_FOUND
CUSTOMER_AMBIGUOUS
PRODUCT_NOT_FOUND
PRODUCT_AMBIGUOUS
PRICE_MISSING
INSUFFICIENT_INVENTORY
STALE_VERSION
ACTION_EXPIRED
ACTION_ALREADY_EXECUTED
PERMISSION_DENIED
MODEL_TIMEOUT
TOOL_TIMEOUT
```

## 6. 幂等设计

- 客户端消息使用 `clientMessageId` 防止重复提交。
- 写操作使用 `idempotency_key` 唯一索引。
- 同一 `agent_action` 只能从 `APPROVED` 转为一次 `EXECUTED`。
- 工具超时后先查询业务结果，不能直接重放写操作。
- 正式业务单据记录来源 `AGENT` 和来源 action ID。

## 7. 多租户与安全

- 所有查询以认证上下文中的 `tenant_id` 过滤。
- 模型不能提交或覆盖 `tenant_id`、`user_id`。
- 返回模型的数据进行字段最小化和必要脱敏。
- Agent 会话不替代正式操作日志。
- 正式订单、库存和收款继续遵循现有数据安全设计。
