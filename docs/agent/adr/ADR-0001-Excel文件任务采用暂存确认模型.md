# ADR-0001：Excel 文件任务采用暂存确认模型

状态：Accepted
日期：2026-09-30

## 背景

供应商日常需要处理买家询价表、补数量文件、厂家价格表、到货表和盘点表。现有附件能力只把表格转成文本交给模型，无法可靠保存工作表、原始行号、审核状态和后续写库过程，也无法在聊天之外恢复任务。

## 决策

Excel 文件先进入独立暂存任务，按 `ExcelTask -> ExcelTaskSheet -> ExcelTaskRow` 保存。上传和解析完成后状态为 `READY_FOR_MAPPING`，不直接修改正式业务表。后续阶段依次完成字段映射、商品匹配、异常审核、变更预览和人工确认写入。

## 备选方案

- 继续把完整表格文本塞入 Agent 上下文：实现简单，但不可分页、不可恢复、难以审计，而且模型上下文会快速膨胀。
- 上传后直接写商品或库存：步骤少，但无法安全处理错列、重复行、匹配冲突和版本变化。
- 立即引入通用工作流或多 Agent 框架：当前问题可由简单任务状态和确定性服务解决，引入成本过高。

## 选择理由

- 保留原文件结构和行级证据。
- 将非确定性理解与确定性业务写入分离。
- 支持移动端分页审核和跨会话继续处理。
- 为字段映射模板、版本比较和批量写入提供稳定数据模型。

## 不变量

- 模型不直接访问 Repository。
- 上传和解析不触发正式业务写入。
- 正式写入前必须展示新增、修改、跳过和异常明细。
- 文件任务必须按操作人隔离。
- 原始工作表、原始行号和原始单元格不得被覆盖。

## 回滚方式

关闭 `/excel-tasks` 前端入口并回滚对应 Controller、Service 和 Repository。新建表可保留，不影响现有业务模块。

## 后续
