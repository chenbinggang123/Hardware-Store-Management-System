# ADR-0006：对话生成文件采用确认快照与永久输出记录

- 状态：已采用
- 日期：2026-10-12
- 相关文档：[13-对话生成Excel文件设计与开发记录](../13-对话生成Excel文件设计与开发记录.md)

## 背景

小五已经能读取图片、Word、Excel 和 PDF 附件，并把识别结果整理成明细表。用户希望把这些内容，以及查询结果或口述的清单，直接做成 Excel 文件。现有 Excel 生成能力只服务于 `ExcelTask`，输出记录绑定 `task_id`，并带 7 天有效期。

## 决策

1. **输入是确认快照，不是 OCR 原文。** 模型先在对话中展示表格，再把同一份内容作为工具参数提交；审批卡展示文件名、行数、样例和验算差异，用户确认后才生成。
2. **文件由确定性 Java 生成。** 数字解析、数量×单价验算、求和公式、公式注入转义、文件命名和存储都在 `AgentWorkbookService` 中完成；模型给出的金额只作对照，差异标注而不改写。
3. **复用并泛化输出记录。** `excel_task_output.task_id` 允许为空，新增 `source_type`、`source_id`、`run_id`、`conversation_id`，对话生成的文件与文件任务输出共用存储、下载鉴权和审计。
4. **永久保存，用户自行删除。** 对话生成的文件 `expires_at` 为空；小程序提供“我的文件”页和对话内删除入口；删除时同时清理存储对象与记录。
5. **结果结构化返回。** `AgentRunResult` 与会话历史携带 `files`，小程序渲染文件卡，不从模型文本中解析下载地址。
6. **工具风险为 `R1_DRAFT`。** 生成文件不写业务数据；需要写入价格、库存或订单时必须另行调用对应的 `R2_WRITE` 工具并再次确认。

## 后果

- 用户可以在对话中用任意表头和行生成 Excel，无需先创建文件任务。
- 生成文件的数量会随使用增长，需要在“我的文件”中提供清理入口；后续如需配额可在 `AgentOutputService` 中按操作人统计。
- `ExcelOutputView` 新增 `sourceType` 与 `runId` 字段，旧客户端忽略即可。
- 已有 MySQL 环境需要补列，`schema.sql` 自动处理，也提供独立迁移脚本。
