# 五金店经营 Agent 当前能力与工作流程

> 文档类型：当前实现说明 / 快速入门
>
> 适用范围：`Hardware-Store-Management-System` 中基于 Spring Boot 实现的经营 Agent
>
> 说明：独立目录 `Hardware-Store-Agent` 是用于对比测试的 Codex Agent，不属于本文描述的正式业务 Agent。

## 1. Agent 定位

当前 Agent 是嵌入五金店管理系统后端的单 Agent。微信小程序负责对话、附件上传和人工确认；模型负责理解用户意图、选择工具和解释结果；Spring Boot Harness 负责运行循环、状态保存、安全策略、工具执行和审批恢复；现有 Java 业务服务负责金额、库存、事务、版本、幂等和最终业务写入。

核心原则：

- 模型不能直接访问数据库、Repository、Shell 或任意网络接口。
- 模型只能调用 `AgentToolRegistry` 中注册的白名单工具。
- 查询工具可以自动执行。
- 草稿操作和正式写入都必须先展示预览，再由用户确认。
- 业务事实以工具实时查询结果为准，不允许模型编造客户、商品、价格或库存。
- 正式业务安全由确定性 Java 代码保证，不能只依赖系统提示词。

## 2. 总体架构

```text
微信小程序 Agent 页面（多会话抽屉 + 流式消息区）
        ↓
AgentMessageController
        ↓
认证用户 + 会话历史 + 附件解析
        ↓
AgentStreamingService（异步执行 + 增量结果持久化）
        ↓
OpenAI-compatible Model Gateway（SSE）
        ↓
AgentHarness 有限循环
        ↓
AgentToolRegistry
        ↓
AgentPolicyEngine → AgentToolExecutor → Java 业务服务
        ↓                    ↓
只读工具直接执行        写工具生成确认预览
        ↓                    ↓
结果返回模型          WAITING_APPROVAL
                             ↓
                      用户确认或取消
                             ↓
                      恢复原 Run 继续执行
```

### 2.1 主要组件

| 组件 | 职责 |
| --- | --- |
| `AgentMessageController` | 接收消息、附件、会话和审批请求，取得当前登录操作人 |
| `AgentConversationService` | 创建会话、保存 Run 关联、读取最近对话历史 |
| `AgentAttachmentService` | 保存和解析附件，将识别内容加入模型输入 |
| `AgentStreamingService` | 立即返回 Run，在后台执行模型循环并把文本增量写入 Run |
| `OpenAiCompatibleModelGateway` | 组装模型消息和工具定义，解析同步响应或 SSE 文本、工具调用分片 |
| `AgentHarness` | 执行有限模型循环，处理完成、失败、暂停和恢复 |
| `AgentContextManager` | 装配会话上下文，保存和恢复工具结果，检测重复调用 |
| `AgentToolRegistry` | 注册并查找模型可以调用的白名单工具 |
| `AgentPolicyEngine` | 根据工具风险等级决定自动执行、等待确认或拒绝 |
| `AgentToolExecutor` | 执行策略检查、预览、工具调用和生命周期 Hook |
| `AgentApprovalService` | 保存待确认动作，处理抢占、超时、取消和恢复执行 |
| `AgentRunStore` | 创建、读取和保存 Agent Run |
| `AgentRunResultFactory` | 生成统一运行结果和结构化确认卡片 |

## 3. 一次消息的工作流程

### 3.1 接收用户输入

小程序的新消息默认调用：

```text
POST /api/agent/messages/stream
```

后端首先取得可信的登录操作人 `operatorId`，然后创建或恢复会话。如果消息携带图片、Excel 或 CSV 等附件，系统先解析附件，再把解析结果作为不可信业务材料加入模型输入。接口创建 Run 后立即返回 `RUNNING`，模型循环在线程池中继续执行。

模型网关使用 OpenAI-compatible SSE 读取真实文本增量，并持续更新当前 Run 的 `output`。由于小程序现有入口仍使用 CloudBase `callContainer`，页面通过短间隔查询 Run 获取新增内容并逐步渲染；这不是预先生成完整答案后的模拟打字。页面隐藏后只停止查询，不会中止后端任务，重新进入页面可继续恢复。

原同步接口仍保留，供兼容调用或测试使用：

```text
POST /api/agent/messages
```

同一会话最多读取最近 10 个 Run 的用户输入和 Agent 回复作为上下文。每次发送新消息都会创建新的 `AgentRun`。

### 3.2 有限模型循环

Harness 把系统规则、会话历史、当前输入、已有工具结果和白名单工具交给模型。模型可以：

1. 直接返回最终回答；
2. 请求调用一个或多个工具。

工具执行结果会重新加入当前 Run 的上下文，再交给模型继续判断，直到模型返回最终回答或运行被暂停、失败。

当前限制：

- 每个 Run 最多调用模型 6 次；
- 每个 Run 最多调用工具 10 次；
- 同一个工具和完全相同的参数不能在同一 Run 中重复调用；
- Run 默认有效期为 30 分钟；
- 模型返回空结果、重复调用、超过限制或工具异常时安全停止。

### 3.3 工具风险与审批

| 风险等级 | 含义 | 当前策略 |
| --- | --- | --- |
| `R0_READ_ONLY` | 只读查询 | 自动执行 |
| `R1_DRAFT` | 创建或修改草稿 | 生成预览，等待用户确认 |
| `R2_WRITE` | 正式业务写入 | 生成预览，等待用户确认 |
| `R3_SENSITIVE` | 敏感操作 | 当前拒绝执行 |
| `R4_RESTRICTED` | 受限操作 | 当前拒绝执行 |

需要确认时，Harness 会保存：

- 工具调用 ID；
- 工具名称；
- 工具参数；
- 已执行工具的上下文；
- 结构化影响预览；
- 过期时间。

Run 随后进入 `WAITING_APPROVAL`。小程序直接渲染结构化预览卡，不从自然语言回复中解析金额、库存或业务状态。

### 3.4 用户确认与恢复

小程序调用：

```text
POST /api/agent/runs/{runId}/approval
```

确认流程会校验操作人、Run 状态和有效期，并通过原子抢占避免重复点击造成重复执行。批准后，工具重新经过策略检查，再执行真实业务操作；随后恢复原 Run 的工具上下文，让模型继续生成最终说明。

用户拒绝后 Run 进入 `CANCELLED`；确认超时后进入 `EXPIRED`。如果业务写入已经成功，但模型生成说明失败，Run 仍按 `COMPLETED` 处理，并明确提示业务已经成功执行。

### 3.5 中途取消任务

运行中或等待确认的任务可以调用：

```text
POST /api/agent/runs/{runId}/cancel
```

后端会校验任务所有人，并以单条数据库更新把 `RUNNING` 或 `WAITING_APPROVAL` 原子转换为 `CANCELLED`，同时清理待确认动作。运行中的后台 Future 会收到线程中断，Harness 也会在模型返回、工具执行和最终保存前检查取消状态。

取消更新会递增乐观锁版本，因此即使取消请求与模型完成同时发生，旧的后台任务也不能把已经取消的 Run 重新覆盖为 `COMPLETED` 或 `FAILED`。已经进入终态的任务不能再次取消；重复取消同一个已取消任务按幂等结果返回。

## 4. 当前已注册工具

当前共注册 10 个模型可调用工具：4 个只读工具、2 个草稿工具和 4 个正式写入工具。

### 4.1 客户查询

#### `search_customers`

- 风险：`R0_READ_ONLY`
- 输入：客户姓名或手机号关键词 `keyword`
- 功能：按姓名或手机号搜索客户，最多返回 10 个候选
- 返回：客户 ID、姓名、脱敏手机号、客户类型和当前欠款
- 限制：多个同名客户时只返回候选，模型不得擅自选择

### 4.2 商品查询

#### `search_products`

- 风险：`R0_READ_ONLY`
- 输入：商品名称、条码、规格或厂商关键词 `keyword`
- 功能：搜索已上架商品，最多返回 10 个候选
- 返回：商品 ID、名称、规格、单位和零售价
- 限制：不返回下架商品；实时库存需继续调用 `check_inventory`

### 4.3 库存查询

#### `check_inventory`

- 风险：`R0_READ_ONLY`
- 输入：`productId`
- 功能：按商品 ID 查询实时库存
- 返回：商品 ID、商品名称、库存数量和库位
- 说明：商品没有库存记录时，库存数量按 0 返回

### 4.4 销售草稿读取

#### `get_sales_draft`

- 风险：`R0_READ_ONLY`
- 输入：`draftId`
- 功能：读取当前操作人名下销售草稿的完整内容
- 返回：草稿版本、客户、商品明细、订单金额、已收金额、欠款影响和库存充足状态
- 用途：修改或正式提交草稿前获取最新版本和业务状态

### 4.5 销售草稿创建

#### `create_sales_draft`

- 风险：`R1_DRAFT`
- 必填输入：`customerId`、至少一个商品的 `productId` 和 `quantity`
- 可选输入：商品成交价 `price`、本次已收金额 `receivedAmount`
- 功能：为指定客户创建销售草稿
- 价格规则：未指定成交价时，由业务服务按历史价格或客户类型价格计算
- 业务影响：只创建草稿，不生成正式订单、不更新客户欠款、不扣减库存

### 4.6 销售草稿修改

#### `update_sales_draft`

- 风险：`R1_DRAFT`
- 输入：`draftId`、`draftVersion`、`customerId`、完整商品列表和可选已收金额
- 功能：完整替换草稿中的客户、商品、数量、价格和已收金额
- 并发控制：使用草稿版本号阻止旧数据覆盖新版本
- 限制：不支持局部 Patch；必须提交修改后的完整草稿
- 业务影响：不生成正式订单、不更新客户欠款、不扣减库存

### 4.7 正式提交销售草稿

#### `commit_sales_draft`

- 风险：`R2_WRITE`
- 输入：`draftId`、`draftVersion`
- 功能：将销售草稿提交为正式销售单，并更新客户欠款
- 提交前检查：草稿版本和库存充足状态
- 确认预览：客户、商品明细、订单总额、已收金额、新增欠款、提交后欠款和库存状态
- 幂等：幂等键由 `runId` 和 `draftId` 确定性生成，模型不能提供或修改
- 限制：创建正式销售单后不会自动出库

### 4.8 新增商品

#### `create_product`

- 风险：`R2_WRITE`
- 必填输入：商品名称 `name`、唯一条码 `barcode`
- 可选输入：规格、单位、零售价、批发价、老客户价、进价、初始库存、库位、厂商和上下架状态
- 功能：创建商品，同时建立初始库存记录
- 默认值：初始库存为 0、商品默认上架、库存预警阈值为 10
- 返回：商品 ID、库存记录 ID 和商品摘要

### 4.9 商品上下架

#### `change_product_status`

- 风险：`R2_WRITE`
- 输入：`productId`、目标状态 `status`
- 状态：`1` 表示上架，`0` 表示下架
- 功能：修改指定商品的上下架状态
- 确认预览：商品名称、条码、当前状态和目标状态
- 要求：调用前应先通过搜索确认唯一商品 ID

### 4.10 库存盘点调整

#### `adjust_inventory`

- 风险：`R2_WRITE`
- 输入：`productId`、盘点后的实际库存 `actualQuantity`、调整原因 `reason`
- 功能：把账面库存调整为指定的实际数量
- 确认预览：商品名称、调整前库存、调整后库存、变化数量和原因
- 说明：输入的是调整后的最终数量，不是增加量或减少量
- 兼容：商品没有库存记录时会创建库存记录

## 5. 典型销售开单流程

以“给老王开两把东成电钻，先记账”为例：

```text
用户输入自然语言需求
→ search_customers 搜索老王
→ search_products 搜索东成电钻
→ 多候选时询问用户，不擅自选择
→ check_inventory 查询实时库存
→ create_sales_draft 请求创建草稿
→ 展示草稿预览，等待第一次确认
→ 确认后创建销售草稿
→ 用户可以继续修改草稿
→ 用户明确要求正式提交
→ get_sales_draft 读取最新草稿和版本
→ commit_sales_draft 请求正式提交
→ 展示订单和欠款影响，等待第二次确认
→ 确认后创建正式销售单并更新客户欠款
→ 不自动出库
→ 模型生成最终说明
```

销售流程因此采用两阶段确认：

```text
确认创建草稿
→ 草稿可检查和修改
→ 再确认提交正式销售单
```

## 6. 会话、附件与运行状态

当前支持：

- 创建、切换和恢复历史会话；
- 根据首条消息生成会话标题，并允许用户重命名；
- 在不存在活动 Run 时删除历史会话；
- 移动端会话抽屉、当前会话标题和新建会话入口；
- 模型输出增量展示、网络重试和页面恢复后续传；
- 中途取消运行中或等待确认的任务；
- 保存每轮用户输入和 Agent 回复；
- 上传并解析图片、Excel 和 CSV 等附件；
- 将附件内容加入模型输入；
- 查询等待确认的 Run；
- 页面刷新后恢复确认卡；
- 记录工具调用 Trace；
- 记录工具成功、失败和耗时。

Run 状态包括：

```text
CREATED
RUNNING
WAITING_USER_INPUT
WAITING_APPROVAL
COMPLETED
FAILED
CANCELLED
EXPIRED
```

当前实现主要使用 `RUNNING`、`WAITING_APPROVAL`、`COMPLETED`、`FAILED`、`CANCELLED` 和 `EXPIRED`。虽然枚举中存在 `WAITING_USER_INPUT`，模型追问目前通常会作为本次 Run 的最终回答保存为 `COMPLETED`；用户回复时在同一 Conversation 中创建新的 Run。

## 7. 当前尚未实现为 Agent 工具的能力

以下业务虽然部分可能已有普通页面或 REST API，但当前没有注册成模型可调用的 Agent 工具：

- 新增、修改或删除客户；
- 新增或修改供应商；
- 创建采购单和采购到货；
- 销售出库；
- 收款和退款；
- 删除商品或业务数据；
- 查询经营报表、利润和日报；
- 查询正式订单列表及详情；
- 独立的历史成交价查询工具；
- 取消或作废正式销售单；
- Excel 批量任务的模型工具调用。

Excel 文件任务已经具备独立的确定性后端流程，但没有通过 `AgentToolRegistry` 暴露给模型，因此不属于当前 10 个 Agent 工具。

## 8. 当前能力摘要

当前 Agent 可以完成：

```text
查客户
+ 查商品
+ 查实时库存
+ 新增商品
+ 商品上下架
+ 盘点调整库存
+ 创建、查看和修改销售草稿
+ 人工确认后提交正式销售单
```

它目前是一套面向进销存高频操作的、带人工审批和可恢复状态的业务 Agent，而不是拥有任意系统权限的通用智能体。
