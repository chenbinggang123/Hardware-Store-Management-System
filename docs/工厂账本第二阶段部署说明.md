# 工厂账本第二阶段部署说明

本阶段将工厂账本从微信小程序本地存储迁移到 Spring Boot + MySQL。小程序仍保留本地回退：未配置云托管时可以演示；配置云托管后，云端请求失败会显示错误，不会悄悄写入另一份本地账。

## 1. 本阶段新增内容

- `factory_ledger`：一家工厂一本账。
- `factory_ledger_transaction`：拿货、退货、收款流水，金额使用整数“分”。
- `factory_ledger_settlement`：每家工厂每个月的结账进度。
- Spring Boot `/api/factory-ledgers` 接口。
- 小程序后端 Agent 已注册账本查询、账本明细、月结汇总、新建账本、记账和结算状态工具。
- `source_purchase_document`：保存源头厂商订单结构化结果，并关联原始 `agent_attachment` 和正式采购单。
- Agent 可将图片、表格、PDF、Word 或 MP4 厂商订单生成确认预览；MP4 最多抽取 6 张代表帧。
- 图片和视频代表帧可由后端直接调用腾讯云“表格识别 V3”，没有检测到表格时自动回退“通用文字识别（高精度版）”。
- OCR 结果保留原始商品名称和数字，只生成待审核草稿；Agent 不会按常识擅自把“航量”等门店商品名称改写成别的词。
- 小程序优先调用云托管接口，未配置云环境时才使用本地存储。
- 新建账本、记账和更新结账进度均写入 `operation_log`，操作人来自登录令牌。

## 2. 本地验证

### 2.1 准备 MySQL

确认 MySQL 已启动，并存在 `hardware_store` 数据库。默认本地配置为：

```text
地址：127.0.0.1:3306
数据库：hardware_store
用户名：root
密码：root
```

如实际环境不同，启动前设置：

```powershell
$env:DB_HOST="实际地址"
$env:DB_PORT="3306"
$env:DB_NAME="hardware_store"
$env:DB_USERNAME="实际用户名"
$env:DB_PASSWORD="实际密码"
```

### 2.2 建表并启动后端

后端启动时会自动执行 `src/main/resources/schema.sql`，其中已经包含三张账本表和 `source_purchase_document`。正式数据库执行前建议先备份。

在项目根目录运行：

```powershell
.\run-dev.ps1
```

默认接口地址为 `http://localhost:8084/api`。

### 2.3 运行自动化测试

仓库自带的 `mvnw.cmd` 当前内容异常，暂时使用项目内置 Maven：

```powershell
cd .\springboot-demo
..\tools\apache-maven-3.9.14\bin\mvn.cmd -Dtest=FactoryLedgerServiceTest test
```

## 3. 微信小程序验证

1. 用微信开发者工具打开 `miniprogram` 目录。
2. 确认 `miniprogram/config/cloud.js` 中：
   - `envId` 是当前云开发环境。
   - `serviceName` 是 `hardware-store-api`。
   - `apiPrefix` 是 `/api`。
3. 编译后重新登录。
4. 从“工作台 → 更多经营工具 → 工厂账本”进入。
5. 新建测试账本，期初余额填写 `128.50`。
6. 记录拿货：数量 `40`，单价 `2.64`，预期本月拿货 `105.60`、当前应收 `234.10`。
7. 登记收款 `50.00`，预期当前应收变为 `184.10`。
8. 进入“月底结账”，将状态从“待汇总”改为“已确认”。
9. 重新编译或换一台登录设备，确认同一账本仍然存在，以验证数据已经写入云端数据库。

## 4. 云托管发布

1. 先备份生产 MySQL。
2. 使用 `springboot-demo/Dockerfile` 重新构建并发布 `hardware-store-api` 服务。
3. 在云托管环境变量中配置 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USERNAME`、`DB_PASSWORD`。
4. 配置小程序 Agent 模型：
   - `AGENT_MODEL_ENABLED=true`
   - `AGENT_MODEL_BASE_URL`：OpenAI、DeepSeek 或其他兼容 Chat Completions 工具调用协议的地址。
   - `AGENT_MODEL_NAME`：实际模型名称。
   - `AGENT_MODEL_API_KEY`：只放在云托管密钥环境变量中，不得写入 Git 或小程序。
5. 配置附件能力：
   - `AGENT_ATTACHMENT_STORAGE=cos`
   - `COS_SECRET_ID`、`COS_SECRET_KEY`、`COS_REGION`、`COS_BUCKET`
   - `OCR_PROVIDER=tencent`
   - `TENCENT_OCR_SECRET_ID`、`TENCENT_OCR_SECRET_KEY`：腾讯云 CAM 子用户密钥，只授予 OCR 调用所需的最小权限。
   - `TENCENT_OCR_REGION`：可选；腾讯云 OCR 当前不强制地域时可以留空。
   - `TENCENT_OCR_TIMEOUT_SECONDS`：可选，默认 `45`。
   - `AGENT_ATTACHMENT_MAX_SIZE_BYTES` 默认 `31457280`（30 MB）。
   - Docker 镜像已经安装 FFmpeg，默认使用命令 `ffmpeg`。
6. 不再需要另外部署 OCR 服务器，也不需要填写 `AGENT_ATTACHMENT_OCR_URL`。该变量只作为旧 HTTP OCR 适配器的兼容入口保留。
7. 不配置 OCR 时，图片和视频会安全保存并显示“等待识别”，不会伪造识别结果。
8. 上传一张手写收据做验证：后端应先调用表格识别 V3，将原始识别值交给 Agent 生成确认卡；用户修改并确认后才保存采购凭证或账本记录。
9. 表格识别失败或没有结构化表格时，后端会自动调用通用高精度识别。两个接口均失败时，附件保留，但不会生成虚假的订单数据。
10. 确认服务容器启动日志没有 SQL 初始化错误。
11. 使用小程序登录后完成一条测试账本和一笔测试流水。
12. 在 MySQL 中确认账本表和 `source_purchase_document` 出现对应记录，再清理测试数据。

## 5. 上线前必须检查

- 数据库已备份。
- 登录令牌正常，未登录请求返回 401。
- 同一本账重复收据编号会被拒绝。
- 拿货增加应收，退货和收款减少应收。
- 月份切换时上月余额正确结转。
- Agent 查询金额与账本页面金额一致，模型不自行计算月度应收。
- Agent 新建账本、记账、更新结算状态和保存厂商订单时都会等待用户确认。
- 只说“保存厂商订单”不会自动入库，只有明确要求入库时才增加库存。
- 相同供应商和厂商单号不会重复保存。
- MP4 上传后最多抽取 6 张代表帧，且原视频仍与凭证关联。
- OCR 原文、低置信度数字和金额验算差异会显示给用户审核，程序不会静默覆盖原值。
- 小程序断网或云端失败时明确报错，不把正式账悄悄写到本地。
