# 当前实现与前后端修正说明

> 2026-10-23 商品与采购统一：商品总页支持全部商品和源头厂商进货账本；进入一家厂商可查看该厂商品与进货单。商品库移除开单按钮，手动补录改为紧凑表单，图片、条码、批发价等默认折叠。新采购使用统一单据编辑页的 `PROCUREMENT` 类型，`customerName` 为源头厂商，`sourceDocumentNumber` 为供应商原单号。确认采购单时自动匹配或新增商品、更新进价并增加库存；再次确认同单不重复入库，同一操作人重复录入同厂商原单号会被拒绝。商品数量可直接手动修正。修改、作废、删除采购单会撤回该单库存变动；数量不足撤回时拒绝操作，保留原单。采购单不记入工厂客户拿货账本，也不计入拿货净额。库存仍采用整数数量，采购小数数量须更换单位后确认。厂商账本直接汇总统一采购单，不另建一套采购录入流程。

> 样单识别约定：供应商票面“销售清单”“送货单”按本店采购理解。供应商取票头、本店为买方；名称不清和日期不清保留待核对。数量栏拆分数量与单位，续行符号仅在前项明确时继承名称。手写加项、明细合计与实付差异保留来源说明，不倒推商品数量或单价。所给图片用于核对规则，未直接写入业务数据。

> 2026-10-23 金额展示收敛：工厂账本只突出“总共还需付”，按截至今天的期初余额 + 拿货 − 退货 − 收款累计计算；月份仅用于翻单据，不影响当前累计需付金额。多付金额单独显示，不抵消其他工厂欠款。不再展示或手动维护“已对账 / 已结清”等进度，旧月底结账链接跳转工厂账本。历史状态字段仅为兼容保留，不参与当前需付金额计算。

> 2026-10-23 账本界面收敛：详情页改为“翻单据”，默认日期倒序，支持全部、拿货单、退货单、收款分类，展开查看明细；已删除的错单和抵消记录不再出现在日常列表。拿货与退货统一使用快捷开单，通过 `BillingContent.documentType`（`PURCHASE` / `RETURN`，历史默认拿货）保存和记账；退货减少应收，图片及 Excel 标题区分类型，月度开单金额为扣除退货后的净额。旧拿货/退货登记链接转到开单页，原登记页只负责收款。余额计算与后台账务痕迹继续保留，不在日常翻单据列表中展示。

> 2026-10-23 单据管理归属修正：草稿和从未入账的单据由开单记录管理。一旦进入工厂账本，开单记录不允许删除、作废或退回草稿（即使对应流水已冲销），统一到账本处理。账本来源流水的“删除单据”会抵消有效账款并删除原单，保留原流水与冲销痕迹。接口为 `DELETE /api/billing/ledgers/{ledgerId}/transactions/{transactionId}/document`，服务端校验来源、账本及原单创建人。

## 前后端修正

| 主题 | 当前实现与规则 |
| --- | --- |
| 真实数据 | 小程序 API 已移除内置模拟业务回退；失败不能视为保存成功。默认后端配置为 MySQL |
| 商品与库存 | 商品页面取消上下架入口；未建库存记录显示“未记录”；盘点可先创建库存记录。商品资料更新不直接覆盖库存数量 |
| 删除商品 | 有出入库或盘点日志时拒绝删除；无此类日志时清理关联库存记录后删除 |
| 快捷开单 | 支持编辑、保存确认、图片及 Excel 导出，以及选择工厂账本记账。确认、导出、记账是独立动作 |
| 开单记录 | 按当前操作人查询，支持单号、客户、商品关键词搜索、全部 / 草稿 / 已保存 / 已作废状态筛选与分页，展示是否记入账本。状态筛选在数据库分页之前执行 |
| 开单暂存 | 编辑时即时写入当前账号在本机的暂存，并启用未保存离开提醒。重新进入可继续填写或丢弃；保存成功后清理暂存。服务器单据已更新时，可明确选择恢复为新单，不覆盖原单；断网时仍可恢复本机内容。暂存不是云端草稿，不跨设备同步 |
| 草稿批量清理 | 记录页点“批量清理草稿”进入草稿筛选，选择单张或已加载草稿，每次最多 100 张。删除前确认；后端锁定并校验全部选择，混入已保存、已作废或不存在单据时整体拒绝，不部分删除。成功后清理相应本机暂存 |
| 单据记账 | 只允许已确认且有单号的单据。工厂账本中记为“拿货”，来源为 `BILLING`，按单号查询已有记录避免重复记账；已入其他账本时拒绝再次转记 |
| 单据作废 | 草稿直接修改；已确认单据可标为 `VOIDED`。若已记账则同时冲销，保留原单和流水；再次作废返回现有结果 |
| 工厂账本 | 可编辑工厂名称、联系人等资料；资料编辑不修改金额与历史流水 |
| 流水冲销 | 原流水标记 `REVERSED`，新增关联原流水的负金额记录，来源 `REVERSAL`。冲销记录不可再冲销，原流水不可重复冲销 |
| 对账展示 | 界面统一为“未对账 / 已对账 / 已结清”；后端兼容原状态值，新增流水不覆盖既有月结状态 |
| 月度汇总 | 独立页面展示开单总额、作废数、各工厂拿货、退货、收款及余额；数据源是快捷开单与工厂账本 |
| 登录 | 运行时使用 JPA 持久化 Token，数据库保存 SHA-256 摘要；默认有效期 43200 分钟（30 天），使用时按续期节奏延长。退出、改密码或禁用账号会撤销相应会话 |
| 操作人 | 商品、采购、销售、库存等修改逐步使用当前认证操作人，替代固定管理员 ID |
| 设置 | 原 `/settings/backup`、`/settings/restore` 模拟接口已移除，小程序不再提供对应操作 |

冲销按操作当天日期记录，因此跨月冲销影响冲销发生月，历史原流水仍保留。月度汇总的开单月份按 `KD-YYYYMM` 单号前缀归集，排除作废金额并单独计数；不能把它理解为按手工填写日期统计的全系统经营报表。当前汇总服务没有按当前操作人过滤开单，设置页仅向管理员展示入口，部署时仍须核对服务端访问范围。

## 主要接口对照

接口均位于 `/api` 下，除登录等放行项外需携带有效 `Bearer` Token。表中省略 `/api` 前缀。

| 方法 | 路径 | 用途与主要参数 |
| --- | --- | --- |
| GET | `/billing/records` | 开单记录；`keyword`、`status`（空 / `DRAFT` / `CONFIRMED` / `VOIDED`）、从 0 开始的 `page`、`size`（默认 20，最大 50） |
| DELETE | `/billing/documents/drafts` | 批量清理当前操作人的草稿；请求体 `{ "ids": [1, 2] }`，最多 100 项，返回 `deleted` 数量 |
| POST / PUT | `/billing/documents` / `/billing/documents/{id}` | 创建或保存单据 |
| POST | `/billing/documents/{id}/confirm` | 确认单据；请求体含 `version` |
| GET | `/billing/documents/{id}/ledger` | 查询记账状态，包含 `posted` 和已记账时的 `reversed` 等字段 |
| POST | `/billing/documents/{id}/ledger` | 记入工厂账本；可传 `{ "ledgerId": 1 }`，否则使用单据内的账本 ID |
| POST | `/billing/documents/{id}/void` | 作废；可传 `{ "reason": "开错了" }` |
| POST | `/billing/documents/{id}/excel` | 生成 Excel 输出 |
| PUT | `/factory-ledgers/{id}` | 更新账本资料 |
| POST | `/factory-ledgers/{id}/transactions/{transactionId}/reverse` | 冲销流水；可传 `reason` |
| POST | `/inventories/ensure?productId=1` | 为商品确保存在库存记录 |
| GET | `/reports/monthly-summary?month=2026-10` | 月度汇总；省略月份为当月，格式 `YYYY-MM` |

图片输出由小程序 `utils/billing-image.js` 处理，不应描述为新增后端图片导出接口。

## 验收清单与证据边界

1. 真实云服务连接失败时，前端展示失败；401 清理会话并返回登录。
2. 已确认单据记账后再次提交，不新增重复流水；改记其他账本被拒绝。
3. 作废已记账单据后，单据变为作废，账本保留原记录并新增冲销记录。
4. 跨月冲销、月度汇总金额与对账状态按当前规则核对。
5. 无库存记录商品可进入盘点；有历史出入库或盘点日志的商品不能删除。
6. 重启服务后有效 Token 可继续使用；退出、改密码、禁用账号后对应 Token 失效。
7. 真机验证单据图片保存、转发和 Excel 输出，确认旧模块入口及权限符合预期。
