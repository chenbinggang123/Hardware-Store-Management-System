# 恒迪五金小程序修改方案

2026-10-21 · 陈炳钢

在线版：https://claude.ai/artifact/SYDoRzqFt8Yi6wBZLAJMn5

## 背景与目标

这次改动不加新业务，只让系统在我不在家时也能稳定、可信地给爸妈用。真实用户是父母，我在学校远程维护，所以数据不能丢、不能被无故踢下线、出了问题要我先知道。

- **P0（本周）**：修掉会覆盖正式数据的启动脚本；登录态持久化。
- **P1（下周起）**：账本能作废和冲销；出错自动通知我，爸妈能一键反馈。
- **P2（之后）**：月底对账单一键发微信；历史账迁移。

推进期间冻结其他新功能，只修爸妈实际遇到的问题。

## P0 数据安全：启动不再改写正式数据

生产环境每次启动都可能把真实库存、价格和欠款改回演示值，必须最先修。

**问题**：`application.properties` 默认启用 `mysql` 配置，`application-mysql.properties` 里是 `spring.sql.init.mode=always`，启动时会执行 `data.sql`。`data.sql` 对 product、customer、inventory、purchase_order、sales_order、inventory_log 都用了 `ON DUPLICATE KEY UPDATE`，id 相同的正式记录会被重写。app_user 只更新 id，管理员密码不受影响。

**修改**

1. 先在云托管控制台确认是否已设置 `SPRING_SQL_INIT_MODE=never`；没有就立即加上并重新发布，这是当天就能生效的止血。
2. 代码里把默认值改成 `spring.sql.init.mode=${SQL_INIT_MODE:never}`，只在本地脚本 `run-dev.ps1` 里设为 `always`。
3. 把 `data.sql` 改名为 `demo-data.sql`，只在开发配置里引用；演示数据改用 `INSERT IGNORE`，就算误跑也不覆盖。
4. `schema.sql` 继续只用 `CREATE TABLE IF NOT EXISTS`；以后改表一律走 `docs/agent/migrations` 里的迁移脚本，发布前手动执行。
5. 发布后核对一遍 id 为 1–3 的商品、客户和库存，确认没有被改过；如果已经被改，用备份或操作日志恢复。

**备份与恢复演练**

- 确认 CloudBase MySQL 开启了自动备份，保留至少 7 天。
- `scripts/backup` 里的脚本加一个每周导出，存到另一处（例如 COS 或自己电脑）。
- 每学期一次：把备份恢复到一个空库，核对商品数、账本数和任意一家工厂的当前应收。对得上才算备份可用。

**验收**：生产服务重启两次后，任意一条真实商品的库存和价格保持不变；完成过一次恢复演练。

## P0 保持登录：发布和重启不再踢人

令牌改存数据库、有效期改为 30 天且使用中自动续期，爸妈一个月内不用重新登录。

**问题**：`AuthTokenStore` 把令牌放在 `ConcurrentHashMap` 里，有效期 8 小时。云托管每次发布、重启或扩容，所有人都会收到 401 被带回登录页；多实例时请求落到另一台也会 401。

**修改**

1. 新增表 `auth_token`：`token_hash CHAR(64)` 主键（只存 SHA-256，不存明文）、`user_id`、`expires_at`、`last_seen_at`、`device`、`create_time`，索引 `(user_id)`、`(expires_at)`。迁移脚本放在 `docs/agent/migrations`。
2. `AuthTokenStore` 保留现有方法签名（`createSession` / `getSession` / `removeSession`），内部改读写该表，调用方和 `AuthInterceptor` 不用动；可加一层 1 分钟的内存缓存减少查库。
3. 滑动续期：`getSession` 时如果距 `last_seen_at` 超过 1 天，把 `expires_at` 顺延到现在 + 30 天。
4. `auth.token.ttl-minutes` 默认改为 43200（30 天）；过期令牌由每天一次的定时任务清理。
5. 禁用账号、改密码时删除该用户全部令牌；设置页加“退出其他设备”。
6. 小程序 `utils/api.js` 已在 401 时跳登录页，无需改动。

**顺手修掉**

- 登录失败限速：同一账号连续错 5 次锁 10 分钟。
- 生产库去掉默认的 `root/root`，连接串打开 SSL。

**验收**：登录后重新发布后端，小程序不用重新登录；`AuthTokenStoreTest`、`AuthHttpTest` 更新后全部通过。

## P1 工厂账本：作废与红字冲销

记错的流水不删除，而是一键生成一条金额相反的冲销记录，应收立即恢复，原记录保留可查。

**现状**：`factory_ledger_transaction` 有 PURCHASE（拿货）、RETURN（退货）、PAYMENT（收款）三种类型，只能新增，记错后没有正式的修正方式。

**修改**

1. 表加字段：`status`（ACTIVE / REVERSED，默认 ACTIVE）、`reversal_of_id`、`reverse_reason`、`reversed_by`、`reversed_at`。
2. 新接口 `POST /factory-ledgers/{id}/transactions/{txId}/reverse`，参数是原因：
    - 在同一事务里插入一条同类型、`amount_cents` 为负数的记录，`reversal_of_id` 指向原记录，`receipt_no` 留空以避开唯一索引。
    - 原记录改为 REVERSED；已冲销的不能再冲销，冲销记录本身也不能再冲销。
    - 写 `operation_log`，记录谁、何时、原因。
3. 汇总代码按类型累加 `amount_cents`，负数自然抵消，月结和应收算法不用改。
4. 已月结确认的月份：冲销记录记在当前日期，不改动已确认月份的数字，并在流水备注中写明“冲销 X 月 X 日记录”。
5. 小程序：账本明细里每条流水加“记错了”按钮，只问一句原因；已冲销的显示删除线和“已冲销”标签。
6. 小五加 `reverse_factory_ledger_transaction` 工具，风险等级 R2，仍需确认。

**验收**：拿货 105.60 → 冲销 → 当前应收恢复到拿货前；重复点击只生效一次；`FactoryLedgerServiceTest` 增加对应用例。

## P1 异常通知与一键反馈

后端出错、备份失败或爸妈点“反馈”时，我的微信在 1 分钟内收到消息，而不是等电话。

**通知通道**：建一个只有自己的企业微信群，加群机器人，后端用 webhook 发消息（免费、无需审核）。webhook 地址放在云托管环境变量 `ALERT_WEBHOOK_URL`，不写进代码。

**后端告警**

1. 新增 `AlertService`：同一类告警 10 分钟内只发一条，发送失败只记日志，不影响业务请求。
2. 全局异常处理里对 5xx 调用告警，内容包括接口路径、异常类型、用户名和时间，不带金额和客户信息。
3. 备份脚本失败、OCR 或模型服务连续失败 3 次时也发。
4. 每天早上 8 点发一条心跳：昨天开单数、记账数、错误数。没收到心跳就说明服务挂了。

**一键反馈**

1. 设置页和各页报错提示里加“反馈给儿子”：可选一张截图（小程序不能自动截屏，用 `wx.chooseMedia` 从相册选）和一句话。
2. 自动附上：当前页面路径、最近一次错误提示、该用户最近 10 条 `operation_log`、小程序版本号。
3. 存入新表 `user_feedback`（状态：未处理 / 已处理），同时推送到群机器人，带一个只有管理员能打开的详情链接。

**验收**：故意让一个接口报错，1 分钟内收到告警且只收到一条；爸妈从报错处点反馈，我能看到截图和操作记录。

## P2 月底对账单一键发微信

月底在“月底结账”页逐家点一下，就能生成这家工厂的对账单图片并直接发到对方微信。这是手写账最累的一步。

**对账单内容**：工厂名、账期（例如 2026-10）、期初应收、本月拿货明细（日期、单号、金额）、退货、收款、冲销、期末应收，底部店名和联系电话。金额全部由后端用“分”计算，前端只负责画图。

**修改**

1. 后端新接口 `GET /factory-ledgers/{id}/statements/{month}`，返回上述结构化数据；复用现有月结汇总逻辑，不重新写一套。
2. 小程序复用 `utils/billing-image.js` 的 canvas 长图方案画对账单，用 `wx.showShareImageMenu` 直接转发给微信好友或保存相册。
3. 需要电子版时，用 `AgentWorkbookService` 生成 Excel，和销售单导出一致。
4. “月底结账”列表每家工厂显示：未生成 / 已发送（记录发送时间），发完一家自动跳到下一家。
5. 可选：每月 1 号群机器人提醒一次“本月有 N 家待对账，合计应收 ¥X”。

**验收**：用工厂账本部署说明里的测试数据（期初 128.50、拿货 105.60、收款 50.00），对账单期末应收为 184.10，且与账本页一致。

## P2 历史账迁移与切换日

定一个切换日（建议某月 1 号），之前的账只迁余额，之后只在系统里记，避免本子和小程序记两遍。

**做法**

1. 和爸妈一起定切换日，最好在上个月刚结完账的时候。
2. 每家工厂只录入切换日当天的未结余额，作为 `opening_balance_cents`；笔笔明细不必补，除非对方经常问旧账。
3. 电脑版 `.data` 里的记录：写一个一次性导入脚本，先导到测试库，生成“工厂 / 系统余额 / 原始余额 / 差额”核对表，差额全为 0 再导入生产库。
4. 手写账本里的未结账：用已有的单张票据 OCR + 人工确认补录，或直接以余额起账。
5. 商品和价格不一次迁全：开单时勾“记住”自然积累，常卖的一两个月就覆盖了。
6. 切换后第一个月本子继续留着备查，月底把系统对账单和本子对一遍。

**验收**：切换日后第一个月的对账单，每家工厂的期末应收和本子一致。

## 排期、验收与风险

按课余时间粗估约五周做完（周数可按实际进度调整）；前一阶段验收未过不开始下一阶段。

| 阶段 | 时间 | 内容 | 进入下一阶段的验收 |
| --- | --- | --- | --- |
| P0 止血 | 第 1 周 | 启动不改正式数据；登录改存数据库；备份恢复演练 | 重启两次数据不变 |
| P1 敢用 | 第 2–3 周 | 账本作废与冲销；出错自动告警；一键反馈给我 | 冲销后应收复原 |
| P2 省事 | 第 4–5 周 | 月底对账单发微信；每月应收提醒 | 对账单与账本一致 |
| 切换日 | 之后的某月 1 号 | 只迁期初余额；本子留一个月备查 | 第一个月对账单与本子一致 |

**每次发布前**

- [ ] 先备份生产库
- [ ] 本地跑全量测试（先修好现在失败的 `FileCenterServiceTest` 和 `AgentWorkbookEndToEndTest`）
- [ ] 有表结构变化先手动执行迁移脚本
- [ ] 避开店里忙的时段，发完在真机上登录并开一张单

**风险**

- `data.sql` 可能已经改过正式数据：第 1 周先核对 id 1–3 的记录，有问题用备份恢复。
- 学业忙时停滞：P0 必须做完，P2 可以顺延。
- 告警太多导致忽略：限流为同类 10 分钟一条，每天只有一条心跳。
- 云服务费用：云托管、MySQL、OCR、模型每月看一次账单，设置预算告警。
