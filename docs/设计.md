## 一、文档说明
本文档用于说明五金店管理系统的总体设计与各业务模块设计，重点覆盖：
- 项目目标与范围
- 系统架构与技术栈
- 业务模块划分
- 各模块的目标、数据结构、接口规划、业务规则与扩展方向

页面与交互相关内容已独立整理至 [页面设计.md](/F:/Hardware-Store-Management-System/Hardware-Store-Management-System/docs/页面设计.md)。

## 二、项目概述
五金店管理系统面向小微商户的日常经营场景，目标是将传统纸质记录、人工报价、人工找货、手工记账逐步数字化，形成以商品、供应商、客户为基础，以采购、销售、库存为核心，以报表和系统设置为支撑的完整业务闭环。

当前阶段已完成商品管理模块的第一轮设计与开发。本文档继续补充供应商管理、客户管理、进货管理、销售管理、库存管理、报表与统计、系统设置等模块设计，为后续开发提供统一依据。

## 六、商品管理模块设计

### 1. 模块目标
- 统一维护商品基础信息，避免纸质记录分散
- 支持按名称、条码、规格快速搜索商品
- 支持维护零售价、批发价、老客户价和进价
- 支持记录库存数量与库位，提升找货效率
- 通过上下架状态控制商品是否参与销售
- 为后续采购、销售、库存联动提供基础数据

### 2. 适用场景
- 店员录入新商品
- 老板维护商品价格
- 销售时快速搜索商品并确认库存
- 盘点时查看库位和库存数量
- 对暂不销售的商品执行下架管理

### 3. 数据结构设计

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| id | Long | 商品主键 |
| name | String | 商品名称 |
| barcode | String | 条码 |
| spec | String | 规格 |
| unit | String | 单位 |
| unitConvert | String | 单位换算说明，当前阶段以字符串保存 |
| retailPrice | BigDecimal | 零售价 |
| wholesalePrice | BigDecimal | 批发价 |
| oldCustomerPrice | BigDecimal | 老客户价 |
| costPrice | BigDecimal | 进价 |
| stock | Integer | 库存数量 |
| locationId | String | 库位 ID |
| sourceFactory | String | 源头厂商 |
| imageUrl | String | 图片地址 |
| status | Integer | 状态，`1` 为上架，`0` 为下架 |
| createTime | LocalDateTime | 创建时间 |

### 4. 后端接口设计

| 功能 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 新增商品 | POST | `/products` | 新建商品 |
| 编辑商品 | PUT | `/products/{id}` | 按 ID 更新商品 |
| 查询商品详情 | GET | `/products/{id}` | 查询单个商品 |
| 查询商品列表 | GET | `/products` | 支持列表、搜索、筛选 |
| 删除商品 | DELETE | `/products/{id}` | 删除商品 |
| 商品上下架 | PATCH | `/products/{id}/status` | 修改状态 |
| 更新商品图片 | PATCH | `/products/{id}/image` | 修改图片地址 |

商品列表查询参数：

| 参数名 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| keyword | String | 否 | 按名称、条码、规格、厂商搜索 |
| status | Integer | 否 | 按上架/下架状态筛选 |

### 5. 业务规则设计
- 商品名称为核心识别字段，后续可补充唯一性校验
- 商品条码字段预留，后续可接扫码能力
- 下架商品默认不参与销售场景
- 零售价、批发价、老客户价分别对应不同客户策略
- 库存与库位信息用于销售找货和库存盘点
- 单位换算先保留字段，后续可扩展为结构化配置

### 6. 当前阶段实现情况
- 已完成商品实体字段设计
- 已完成商品 CRUD 接口
- 已完成关键字段搜索与状态筛选
- 已完成上下架接口与图片地址更新接口
- 当前开发阶段使用内存存储进行本地联调，后续可平滑迁移到正式数据库

### 7. 后续扩展方向
- 商品分页查询
- 商品分类管理
- 条码/二维码生成与扫码识别
- 图片文件上传
- 商品上下架与销售权限联动
- 商品价格历史与调价日志

### 5. 业务规则设计
- 供应商名称作为主要检索字段

- 同一供应商下可关联多张采购单
- 价格趋势按商品维度和时间维度统计

### 6. 后续扩展方向
- 供应商评级
- 结算周期管理
- 应付账款联动

### 2. 适用场景

- 补货时参考供应商历史价格

- 对供应商进行采购对账

### 4. 后端接口设计

| 功能 | 方法 | 路径 | 说明 |

### 5. 业务规则设计
- 采购单金额由明细汇总自动计算
- 已入库采购单不允许随意修改核心字段
- 入库后同步更新库存数量和最后更新时间
- 同一采购单可包含多个商品明细
- 可基于供应商和商品生成历史进价趋势

### 6. 后续扩展方向
- 采购单打印
- 供应商应付账款联动
- 异常价格提醒
- 批次管理与到货记录

- 销售出库扣减库存

- 库位字段用于实际找货与仓储定位
- 当库存小于等于预警阈值时进入预警列表

### 6. 后续扩展方向
- 多仓库管理
- 库位二维码
- 盘点任务单
- 安全库存与补货建议

## 十二、报表与统计模块设计

### 1. 模块目标
- 汇总采购、销售、库存和财务关键指标
- 提供日报、月报、年报等经营视角
- 支持图表化展示与数据导出

### 2. 适用场景
- 老板查看每日营业情况
- 月度分析采购金额和销售金额
- 查看商品销量排行和库存排行
- 导出经营数据做外部统计

### 3. 数据结构设计
报表与统计模块以聚合结果为主，不单独维护业务主表，数据来源包括：
- 商品表
- 采购单表
- 销售单表

## 十三、系统设置模块设计

### 1. 模块目标
- 统一管理系统用户、角色、权限和运行配置
- 支持数据备份与恢复
- 记录关键操作日志，便于追踪和审计

### 2. 适用场景
- 新增店员账号
- 分配老板、店员、仓库、财务角色
- 导出或恢复系统数据
- 查询关键业务操作日志

### 3. 数据结构设计

用户表：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| id | Long | 用户主键 |
| username | String | 登录账号 |
| password | String | 加密密码 |
| name | String | 姓名 |
| phone | String | 手机号 |
| role | String | 角色，老板/店员/仓库/财务 |
| status | Integer | 状态，启用/停用 |
| createTime | LocalDateTime | 创建时间 |

操作日志表：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| id | Long | 日志主键 |
| operatorId | Long | 操作人 ID |
| module | String | 所属模块 |
| action | String | 操作类型 |
| detail | String | 操作详情 |
| createTime | LocalDateTime | 创建时间 |

### 4. 后端接口设计

| 功能 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 用户列表 | GET | `/settings/users` | 查询用户列表 |
| 新增用户 | POST | `/settings/users` | 新建用户 |
| 编辑用户 | PUT | `/settings/users/{id}` | 更新用户信息 |
| 分配角色 | PATCH | `/settings/users/{id}/role` | 修改角色 |
| 启停用户 | PATCH | `/settings/users/{id}/status` | 启用/停用账号 |
| 备份数据 | POST | `/settings/backup` | 生成备份 |
| 恢复数据 | POST | `/settings/restore` | 执行恢复 |
| 操作日志 | GET | `/settings/logs` | 查询日志列表 |

### 5. 业务规则设计
- 不同角色可访问不同模块
- 密码必须加密存储
- 备份与恢复操作仅允许管理员执行
- 关键数据修改需记录操作日志
- 停用账号后不允许登录系统

### 6. 后续扩展方向
- JWT / Spring Security 接入
- 菜单级权限控制
- 数据字典配置
- 系统参数配置中心
