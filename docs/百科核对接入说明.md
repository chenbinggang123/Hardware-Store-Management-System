# 百科核对接入说明

## 当前链路

图片解析 → 小五按任务整理字段 → 有疑点时调用 `search_product_encyclopedia` → `prepare_billing_document` 保留原文并处理连续规格行 → 自动逐行匹配规格资料 → 编辑页显示原文、建议、解释与来源 → 用户选择或手动修改 → 按既有单据流程保存。

模型即使没有先调用百科查询工具，草稿工具仍会附上匹配的规格资料。后台按商品匹配本地条目，未匹配时不生成建议。不改变确认、库存或价格逻辑。现有草稿不会被批量回填或改写；新生成的识别草稿开始附带资料。

## 内容在哪里维护

- 商品名称、别名及单位候选继续放在 `springboot-demo/src/main/resources/product-encyclopedia/`。
- 分类规格参考放在 `springboot-demo/src/main/resources/product-knowledge/specification-rules.json`。每条包含稳定ID、类别、关键词、标题、解释、规则类型及来源标题和URL。
- 第一版有9类条目：钻头、铰刀、螺纹工具、磨棒、锉刀、批头、量具、管接头、砂纸。
- 参考依据来自《五金商品名称与规格写法参考》。本店磨棒写法没有厂家证据，仅注明本店待核对样例，不能冒充标准。
- 资料随应用启动加载；本轮没有新增在线管理页面、向量数据库、全文联网采集或实时价格服务。

## 工具与结果

`search_product_encyclopedia` 保留原有 `keyword`、`limit`，增加 `category`、`originalSpecification`、`issue`。返回原有商品候选，以及少量相关 `specificationReferences` 和 `specificationAdvice`，不把全部资料交给模型。

单据行新增 `rawName`、`rawSpecification`、`knowledgeAdvice`、`knowledgeReviewValue`，随现有单据JSON保存，不需要新建业务表。原文字段在整理之前捕获；百科来源来自本地可信条目。原始图片本身仍按用户是否主动保存执行文件中心规则。

## 编辑页

有规格候选的行计入待核对筛选，展开后显示“百科核对参考”。用户可采用建议，或保留当前规格；支持复制来源链接。原文和依据始终保留。建议只在对应名称和原规格仍一致时可采用，避免编辑后误用旧建议。已确认或作废单不能通过建议按钮修改。

例如“镀钛钻头／中5、8”可以提出“Φ5.8”候选，但解释保留“可能是多个尺寸”的歧义；数量、价格、金额不变。P120砂纸、中齿平锉、M6丝锥不按直径OCR规则替换。不自动拆分多个尺寸，不把建议加入长期商品记忆。

## 验证与边界

- `SpecificationKnowledgeCatalogTest` 验证分类与来源、有效符号、无匹配回退、查询工具、连续规格行、字段与JSON往返。
- `tools/billing-knowledge.test.cjs` 验证原文保留、主动采用、主动保留、旧建议防误用和已确认单防修改。
- 现有建单、采购库存、连续行及本地草稿恢复测试参与回归。
- 三种手机宽度的浏览器预览使用实际小程序模板和样式；不是微信真机验收，也未调用在线模型验证原照片OCR质量。本轮没有部署。
