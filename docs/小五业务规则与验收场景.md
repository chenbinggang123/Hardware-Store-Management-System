# 小五当前业务规则与验收

共同规则保存在 `springboot-demo/src/main/resources/agent/business-rules.txt`，模型提示与附件处理共用；按能力加载的说明也记录该文件的版本。连续规格行规则由 `HandwrittenItemContinuation.MODEL_RULE` 提供。

当前行为：所有拿货、退货和采购单进入单据编辑页。小五只准备草稿；用户在编辑页确认采购后自动记商品、更新进价并增加库存。单独新增商品不强制条码，商品服务生成内部编号。查询与匹配工具对建单、新增商品能力开放，旧销售及旧源头采购写入工具仍保持停用。

## 固定验收场景

| 用户输入或票据情况 | 应有结果 |
| --- | --- |
| 用户说“这些是我们买的”，票头写销售清单或送货单 | 按本店采购理解，要求建单时使用 PROCUREMENT；不因标题变为本店拿货销售 |
| 辉达 0002050，商品后连续 P5.5、中5、8 等规格行 | 连续多行追溯最近明确名称，保留本行规格、数值及补全证据，待核对 |
| 林光 0000855、0000863 | 同一厂商、不同原单号独立保留；不把后者并进前者 |
| 票面 3014、加项900、旁注3900 | 来源说明保留差异；不反推单价、数量或静默改成一致 |
| 名称、单位、数量或单价无法辨认 | 原文及疑点留在草稿，未知字段留空；不阻塞建立草稿、不猜单位 |
| 上传照片但没有明确任务 | 结合最近对话；已有商品核对任务则继续，无上下文才补问用途 |
| “新增磨棒，3×1-3，单位支”，无条码 | 先搜索避免重复；允许无条码调用商品工具，内部编号由服务生成 |
| “保存采购单” | 建立编辑页草稿，不提前入库；无需另建商品，不二次询问是否建立草稿 |
| “读一下这张单据” | 读取完整单据，不新建单据，不修改库存 |
| 查今天入库后追问“昨天呢” | 延续采购入库主题，按实际确认入库时间查询；草稿、入库、撤回分开 |
| 仅保存原图 | 文件中心留存，不创建采购单 |
| 查询结果含多行商品 | 回复保留完整表头与各列，不变成点号拼接的长列表 |

## 已有自动验证

- `AgentWorkflowContractTest`：三张参考采购单的部分人工整理输入经过真实草稿规范化；验证采购方向、原单号、连续规格、缺项和来源差异保留，验证预览不写业务；验证无条码商品工具与能力工具范围。
- `HandwrittenItemContinuationTest`：多行连续、数字规格和直径符号误识别、新名称切换、冲突与空行、重复处理。
- `ProcurementCatalogIntegrationTest`：采购确认、重复确认、撤回/作废/删除、手工改库存、不同厂商商品与重复原单号等业务链路。
- `AgentCapabilityRegistryTest`、`AgentBusinessToolsTest`、`PrepareBillingDocumentToolTest`：共同规则加载、新建商品、建单及工具确认。

上述采购单样例不是完整的图片 OCR 转录，也不代表在线模型已通过视觉识别测试。上线验收仍应使用原照片和真实聊天，逐项检查 OCR、任务理解、追问次数和草稿内容；本轮未切换模型、调用付费模型评测或部署。
